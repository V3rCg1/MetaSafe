# MetaSafe v0.8.1

19 November 2026 · [English](../../README.md) · [Русский](../../README.ru.md)

## English

This update limits aggregate PDF decoding and adds installation instructions for the desktop app and CLI. Photo, video and Office cleanup retain their existing behavior.

### PDF decoding budget

Earlier versions limited each decoded PDF stream to 8 MiB. A document could still contain many individually acceptable streams and expand far beyond that amount during loading. This happened before MetaSafe could inspect its properties or create a cleaned copy.

The PDF loader now uses a shared 64 MiB budget for successful decoding outputs. Each decoding filter is capped by the smaller of its existing limit and the remaining shared budget. Its output is charged before the next filter or stream is processed. The 8 MiB limit for an individual stream remains in place.

The same budget covers:

- Compressed and plain object streams, including objects loaded on demand to resolve an indirect stream length.
- Cross-reference streams, hybrid cross-reference data and earlier PDF revisions.
- Intermediate outputs of nested compression filters and repeated decoding of the same stream.
- Reconstruction readers, which reuse the original budget instead of creating a new allowance.

Catalog XMP retains a separate 1 MiB bound. Exceeding a decoding limit stops that file. Cleanup does not publish a result, overwrite an existing destination or modify the original. Other files in a batch can continue through the existing per-file error handling.

These are decoding budgets. Parsed objects, file snapshots, output buffers and decoder overhead consume additional memory. The update does not impose a hard limit on total process memory or CPU time. Complex legitimate PDFs can also exceed the budget and be rejected.

### Why lopdf is included locally

The pinned upstream lopdf 0.47.0 API exposes a per-stream limit. An application check after loading would happen too late, and the object filter runs after cross-reference loading. MetaSafe therefore includes a local copy with a shared decoding budget.

The change is used by the common Rust core, so CLI and desktop document operations enforce the same boundary. The original MIT license is retained. [PATCHES.md](../../vendor/lopdf/PATCHES.md) records the upstream package checksum, modified files and removal conditions. Source builds must include `vendor/lopdf`.

### Regression coverage

Seven new tests check the resource boundary and ordinary documents:

| Test case | Expected result |
| --- | --- |
| Seventeen compressed object members of 4 MiB each | Inspection, verification and cleanup reject the document; no copy is published; the original stays unchanged |
| Multiple plain, compressed and nested-filter object streams | A shared small test budget rejects their combined output; a sufficient budget succeeds |
| Cross-reference output before object loading | It consumes the same budget and can stop loading early |
| Intermediate nested-filter output | It counts even when the final stream alone would fit |
| Indirect `/Length` stored in a compressed object | Lazy and eager decoding share the budget |
| Empty `/Filter []` arrays | Plain bytes and object members remain intact and count toward the budget |
| Previous cross-reference revisions | The previous revision does not receive a fresh allowance |

Positive controls also check independent loads, preserved object members and normal cleaned copies. The existing PDF tests cover page content, links, form fields, earlier metadata revisions and publication without overwriting.

### Installation and packaging

Both READMEs now provide direct downloads and separate instructions for macOS Apple Silicon, Windows x64 and Linux x64. They explain FFmpeg, WebView2, system launch prompts, CLI setup and SHA-256 checks. The source-build instructions distinguish the main Tauri app from the older eframe interface.

The release provides desktop packages and CLI executables, plus `SHA256SUMS.txt`. Desktop bundles include the local PDF dependency's MIT notice and the relevant font license. GitHub's automatic source archives are for building the project, not for installing the desktop app.

### Cleanup scope

PDF cleanup removes `/Info` properties and catalog XMP. Page content, annotations, attachments, form values, PDF identifiers and object-level metadata can still contain private information. A passing metadata report does not establish anonymity. Signed, encrypted and PDF/A documents remain subject to the existing cleanup refusals.

### Local release checks

The release candidate passed 48 core/CLI/photo/document tests and two Tauri tests on macOS. Rust formatting, Clippy with warnings denied, TypeScript and the frontend production build passed. The macOS CLI and Tauri application built in release mode; the CLI reported `0.8.1`, the app bundle reported `0.8.1`, and its main window opened. Cross-platform CI results are linked from the GitHub release.

An independent source review found no remaining Critical or Important issues. The managed security diff scan could not resolve this Git checkout and did not complete. This review does not claim a completed automated security scan.

## Русский

Обновление ограничивает суммарную распаковку PDF и добавляет инструкции установки приложения и CLI. Обработка фото, видео и Office сохраняет прежнее поведение.

### Общий бюджет PDF

Раньше при загрузке PDF действовал предел 8 МиБ для каждого распакованного потока. Документ мог содержать много потоков, каждый из которых укладывался в этот предел. Их суммарный объём рос до проверки свойств и создания очищенной копии.

Теперь результаты успешного декодирования учитываются в общем бюджете 64 МиБ. Для каждого фильтра доступен меньший из двух пределов: прежний предел потока или остаток общего бюджета. Результат списывается до обработки следующего фильтра или потока. Предел 8 МиБ на отдельный поток сохраняется.

Один счётчик охватывает сжатые и несжатые потоки объектов, таблицы ссылок и предыдущие ревизии PDF. Он учитывает промежуточные результаты вложенных фильтров и повторную распаковку. Загрузка объекта по косвенной ссылке `/Length` использует тот же счётчик. Восстановление структуры документа также не получает новый бюджет.

Для XMP каталога отдельно сохраняется предел 1 МиБ. Если документ превышает предел, программа останавливает его обработку. Оригинал и существующий файл назначения сохраняются, новая копия не публикуется. Остальные файлы пакета продолжают обрабатываться по прежним правилам.

Бюджет относится к декодированию. Разобранные объекты, снимки файлов, буферы вывода и внутренние данные декодера используют дополнительную память. Жёсткого предела памяти всего процесса или времени CPU в этом обновлении нет. Сложный корректный PDF тоже может превысить бюджет и быть отклонён.

### Локальная копия lopdf

В закреплённой версии lopdf 0.47.0 есть только предел отдельного потока. Проверка после загрузки не защищает раннюю распаковку, а фильтр объектов вызывается после чтения таблиц ссылок. Поэтому в проект включена локальная копия с общим счётчиком.

Патч работает в общем ядре Rust и применяется к документам в CLI и приложении. Исходная лицензия MIT сохранена. В [PATCHES.md](../../vendor/lopdf/PATCHES.md) указаны контрольная сумма upstream-пакета, изменённые файлы и условия удаления локального патча. Для сборки из исходников нужна папка `vendor/lopdf`.

### Проверки

Добавлены семь регрессионных тестов. Они проверяют суммарную распаковку, несжатые потоки, вложенные фильтры, косвенный `/Length`, пустой `/Filter []`, предыдущие ревизии и сохранение содержимого обычной копии. Проверки отдельных вариантов используют загрузчик библиотеки; большой пример из 17 объектов по 4 МиБ проходит через общие функции `inspect`, `verify` и очистки и подтверждает отказ без публикации результата.

Положительные примеры подтверждают, что достаточный бюджет позволяет загрузку, отдельные загрузки не делят остаток и очищенная копия сохраняет проверенные объекты. Прежние тесты PDF проверяют страницы, ссылки, поля форм, старые ревизии метаданных и защиту от перезаписи.

### Установка и файлы релиза

В английском и русском README есть прямые ссылки на сборки и отдельные инструкции для macOS Apple Silicon, Windows x64 и Linux x64. Описаны установка FFmpeg, WebView2, системные запросы при первом запуске, настройка CLI и сверка SHA-256. Инструкции сборки разделяют основное приложение Tauri и старый интерфейс eframe.

Релиз содержит пакеты приложения, исполняемые файлы CLI и `SHA256SUMS.txt`. В пакеты приложения включены лицензия локальной PDF-библиотеки и соответствующая лицензия шрифта. Автоматические архивы GitHub Source code предназначены для сборки проекта.

### Область очистки

Очистка PDF удаляет свойства `/Info` и XMP каталога. Содержимое страниц, аннотации, вложения, значения форм, идентификаторы PDF и метаданные отдельных объектов могут сохранять личную информацию. Успешный отчёт о метаданных не подтверждает анонимность. Прежние отказы для подписанных, зашифрованных документов и PDF/A сохраняются.

### Локальные проверки релиза

На macOS прошли 48 тестов ядра, CLI, фото и документов и два теста Tauri. Форматирование Rust, Clippy с запретом предупреждений, TypeScript и production-сборка frontend прошли без ошибок. CLI и приложение Tauri собраны в release-режиме: исполняемый файл и bundle показывают `0.8.1`, главное окно приложения открылось. Ссылки на результаты проверок разных ОС находятся в релизе GitHub.
